# Product Requirements 模板

按任务规模裁剪，但至少保证“产品文档 + 程序设计文档 + 测试用例文档”三件事是清楚的。

## 1. 产品文档模板

```markdown
# <主题标题>

## 背景

## 目标

## 非目标

## 使用方 / 角色

## 用户流程 / 调用流程

## 功能需求

## 边界条件

## 错误与降级

## 兼容性 / 依赖

## 验收标准

## 风险与待确认项
```

## 2. 程序设计文档模板

```markdown
# <主题标题> 设计说明

## 范围

## 代码位置

## 类与职责

## 输入输出模型

## API / 回调 / 事件

## 关键流程

## 线程 / 缓存 / 持久化 / 通知

## 错误处理与降级

## 兼容策略

## 改动清单
```

## 3. 测试用例文档模板

```markdown
# <主题标题> 测试用例

## 测试目标

## 测试环境

## 正向用例

## 失败用例

## 降级用例

## 边界用例

## 回调 / 返回格式校验

## 回归判定标准
```

## 4. 设计图判断模板

可在产品文档或设计文档中补一句：

```markdown
## 设计图判断

- 本需求需要 / 不需要 单独设计图
- 原因：
```

## 5. 小修模板

对于极小补丁，可简化为：

```markdown
## 目标

## 影响范围

## 验收点
```
