# 控制中心（Control Widget）接入文档

> 面向同事：给**新宿主工程**或花园类项目接入 iOS 18 控制中心按钮时用。  
> 本文写在个人知识库，**不替代**仓库内正式文档；落地以代码与仓库文档为准。  
> 日期：2026-07-25  
> 标签：`#控制中心` `#ControlWidget` `#花园` `#NativeBility` `#iOS18`

---

## 0. 一分钟搞清在做什么

```text
用户点控制中心按钮
  → 宿主 AppIntent.perform（必须在宿主工程 Swift 里）
    → ControlWidgetCore 写 App Group + 打开主 App URL
      → 主 App 起来
        → 游戏调 control/default/getInfo
          → 按 extra.action 跳业务；读完消费
```

| 项 | 说明 |
|----|------|
| 系统下限 | **iOS 18+**（适配器 / Control API） |
| JS 模块名 | `control` |
| 适配器 | `Plugin_control` → `PluginAdapter_control*` |
| App Group | **`group.` + 主包 Bundle ID**（与灵动岛 / 小组件同一套） |
| 花园扩展 | `HYControlWidgetExtension`，Bundle `…ios.HYControlWidget`，Deploy **18.0** |
| Pod 来源 | **内网 Git remote**（同事按此接入即可） |

### 0.1 最重要的硬约束（必读）

> **控制中心按钮的 `AppIntent` 不能只写在 Pod 里。**  
> 必须在**宿主工程**提供 Swift：`AppIntent` + `ControlWidget`，并且 **同时勾选「主 App Target + 控制中心扩展 Target」**。  
> 扩展 `@main` Bundle 要注册**宿主**的 Control，而不是只绑 Pod 内通用 Intent。

违反这条：真机常见「点了完全不跳转」，Debug/Release 表现还可能不一致。

防踩坑说明见 NativeBility 文档与 `pod install` 后的 `Pods/ControlWidgetCore` 内说明（优先读第 10 节链接）。

| 模块 | 谁用 | 作用 |
|------|------|------|
| **ControlWidgetCore** | **主 App + 控制中心扩展** | 写 App Group、`HostedJump` / `HostedOpenApp`、Bootstrap wire |

## 3. Podfile 怎么配（花园模板）

路径：`/Users/lin/Documents/HuaYuann/build/ios/proj/Podfile`

### 3.1 模式

与小组件共用，同事统一用 **remote**：

```ruby
# 'remote' = 内网 git（同事 / 发布 / CI）
# 'none'   = 不接小组件 / 控制中心相关 Pod
WIDGET_MODE = 'remote'

WIDGET_GIT_BASE = 'ssh://git@192.168.13.252:8022/modo_ios'
```

### 3.2 主 App

```ruby
if WIDGET_MODE == 'remote'
  pod 'ControlWidgetCore', :git => "#{WIDGET_GIT_BASE}/mdcontrolwidgetcore.git"
end
```

（主 App 同时常有 `WidgetCommon`，见小组件文档；**不要**把 WidgetUI 链进主 App。）

### 3.3 控制中心扩展

```ruby
target 'HYControlWidgetExtension' do
  if WIDGET_MODE == 'remote'
    pod 'ControlWidgetCore', :git => "#{WIDGET_GIT_BASE}/mdcontrolwidgetcore.git"
  end
end
```

### 3.4 pre_install

`ControlWidgetCore` → **dynamic_framework**（与 WidgetCommon 静态相反，别搞反）。

### 3.5 无专用 install.rb

控制中心 **不像** 小组件有 Intent 自动安装脚本；靠：

1. Pod（remote git）
2. 宿主已有（或新建）双 Target Swift
3. 扩展 `@main` Bundle

`WIDGET_MODE = 'none'` 时主 / 扩展都不要留 Control Pod。

## 4. Xcode 工程步骤

### 4.1 建控制中心 Extension

1. File → New → Target → **Widget Extension**（专门给控制中心用，**不要**和桌面小组件混一个 Target）
2. 花园名：`HYControlWidgetExtension`
3. Bundle ID：`主包.HYControlWidget`（后缀按团队约定，运行时会剥扩展后缀反推主包）
4. Deployment：**18.0**
5. Embed 到主 App
6. App Group 与主 App 一致：`group.<主包ID>`

### 4.2 必须有的宿主源文件（双 Target）

花园参考目录：`build/ios/proj/HYControlWidget/`

| 文件 | Target Membership | 作用 |
|------|-------------------|------|
| `HYControlWidgetOpenApp.swift`（或等价） | **主 App + 扩展** | IntentName、Config、宿主 `AppIntent`、`ControlWidget`、`MainAppWire` |
| `HYControlWidgetBundle.swift` | **仅扩展** | `@main` `WidgetBundle`，注册宿主 Control |

勾选 Membership 漏掉主 App 或漏掉扩展 → 真机不跳、Release 异常。

### 4.3 Bundle 注册方式（正确 vs 错误）

**推荐（花园做法）：** Bundle `body` 里放**宿主**定义的 `ControlWidget`。

**不推荐（真机高风险）：**

```swift
// 仅示意错误方向：把按钮完全绑在 Pod 内通用 Intent
ControlWidgetCoreOpenAppControl<YourDefining>()
```

### 4.4 kind / action 约定（概念）

- kind 常见形态：`{hostBundleId}.HYControlWidget.{launchAction}`
- `hostBundleId`：扩展运行时从 `Bundle.main` 推导，剥掉 `.HYControlWidgetExtension` 等后缀
- 业务 action 示例（花园）：`flower_pick`、`competition`
- **改 kind / Intent 后**：用户须在控制中心 **删除旧控件再添加**，否则点旧控件无效

### 4.5 URL Scheme / Info

- 宿主配置 `openURL`，例：`huayuan6746321359://openFromControlCenter`
- 主 App `CFBundleURLTypes` **必须一致**
- 主 App 链接 **AppIntents**；配置 `SWIFT_VERSION`
- Bootstrap：链上 Pod 后 `ControlWidgetCoreBootstrap +load` 会 wire；`AppDelegate` 再调一次无害

### 4.6 App Group

- 根业务键概念：**`ControlWidget`**，子键 = 业务 `action`
- TTL：**约 30s**（与 Widget / LA launch store 同类工具）
- entitlements：主 App + `HYControlWidgetExtension` 同 group

## 5. NativeBility / JS 调用

### 5.1 路径

```text
control / default / getInfo
control / default / delegate
```

| API | 作用 |
|-----|------|
| `getInfo` | 读「从控制中心打开」的一次性信息 |
| `delegate` | 清理指定 action 或整目录（实现以插件为准） |

适配器通常 **iOS 18+** 才 `isEnabled`。

### 5.2 点击链路（务必按这个排障）

```text
1. 控制中心按钮 → 宿主 AppIntent.perform
2. ControlWidgetCoreHostedJump / OpenApp
   - 写 App Group（ControlWidget / action）
   - OpenURLIntent 打开主 App
3. 主 App 前台 / 冷启动
4. 游戏调 control/default/getInfo
5. 按 extra.action 分支；命中后消费
6. 再调 getInfo 应为空（或等价空对象）
```

### 5.3 getInfo 形态（概念）

```json
{
  "scene": "ctrlCenter",
  "extra": { "action": "flower_pick" },
  "ts": 1234567890,
  "isControlOpen": true
}
```

异常路径插件常返回 `{}` / `{ok:true}`，避免打断主流程——排障时别只看「失败回调」。

### 5.4 时序坑：短重试

后台点控制中心时，主 App 前台回调有时 **早于** App Group 写盘完成。  
建议游戏侧对 `getInfo` 做 **0.3～0.5s 短重试**（1～2 次即可）。

## 6. 新增一个控制中心按钮（同事常做）

以花园模式为例（名称按项目替换）：

```text
1. 在宿主 Swift 增加 IntentName case（action 字符串）
2. 增加对应宿主 AppIntent（title 必须是编译期字面量，不能 rawValue）
3. 增加对应宿主 ControlWidget / 挂到 Definitions
4. 扩展 Bundle 注册该 Control（或统一 allControls）
5. 确认文件勾选：主 App + 扩展
6. 配 SF Symbol / 展示名
7. 编译安装 → 控制中心删除旧控件 → 重新添加
8. 点按钮 → getInfo.extra.action 等于新 case
```

`AppIntent.title`：**只能写字符串字面量**，写 `xxx.rawValue` 会编译失败或元数据不对。

## 7. 推荐操作流程（新工程从头抄）

```text
1. 建 HYControlWidgetExtension（Deploy 18.0，单独 Target）
2. Podfile：WIDGET_MODE=remote；主 + 扩展都引 ControlWidgetCore（git）；动态库
3. pod install
4. 拷贝/新建双 Target Swift（OpenApp + Bundle）
5. Bundle 注册宿主 Control；OpenApp 勾选主 App+扩展
6. App Group = group.<主包ID>
7. 主 App URL Types = 宿主 openURL
8. 真机：添加控制中心控件 → 冷启动点按钮 → getInfo 有 action
9. 再 getInfo 为空；Release 包同样测一遍
```

## 9. 常见踩坑

| 现象 | 原因 | 处理 |
|------|------|------|
| 真机点了完全不跳 | Intent 只在 Pod / 未双 Target | 改回宿主 Intent+Control；删控件重加 |
| Debug 跳、Release 不跳 | Wire / Bootstrap / Intent 未进 Release 主包 | 查 `MainAppWire`、`_ = Intent.self`、Membership |
| `getInfo` 一直空 | App Group、未 write、TTL、已消费、时序 | 查写盘与短重试 |
| `AppIntent.title` 编译失败 | 用了 `rawValue` / 变量 | 改成字面量 |
| 点旧控件无效 | 改过 kind / Intent | 控制中心删除后重加 |
| 与桌面小组件互相影响 | 塞进同一 Extension | 拆成独立 Target |
| pod install 拉不下来 | 内网 Git / SSH 权限 | 确认能访问 `192.168.13.252:8022` |

## 11. 与灵动岛 / 桌面小组件对照

| | 灵动岛 | 桌面小组件 | 控制中心 |
|--|--------|------------|----------|
| 系统 | 16.1+ | 16.1+ | **18+** |
| Pod 开关 | `ACTIVITY_MODE` | `WIDGET_MODE` | 同 `WIDGET_MODE` |
| 主 App Pod | ActivitySDK + CoreDate | WidgetCommon | ControlWidgetCore |
| 扩展 Pod | ActivityUI + CoreDate | WidgetUI + WidgetCommon | ControlWidgetCore |
| 链接 | 动态 | **静态** | **动态** |
| 自动脚本 | 无 | Intent install.rb | 无 |
| JS | `live_activity` | `widget` | `control` |
| 点击落盘根键 | LiveActivityLaunch | WidgetLaunch | **ControlWidget** |

App Group 三者共用 `group.<主包>`，业务目录 / 键名分开，不要互相覆盖。
